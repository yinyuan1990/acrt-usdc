先说结论

曲线路线有两种做法：A. 曲线 → 我们自部署的 Uniswap V3（测试网今天能测）；B. 曲线 → Uniswap V4 + Hook（= pons v2，要等 9.16 官方地址）。A 需要 6 个自研合约（2 新写、1 重写、3 沿用/小改），B 需要 9–10 个。两者都让用户本金进入我们自己写的合约，审计从"建议"变成"必须"。

1. 一个币的四个阶段

2. 方案 A：曲线 → 我们自部署的 V3，需要哪些合约

今天就能在 Arc 测试网测。相对现在的 4 个合约：2 个新写、1 个重写、3 个沿用或小改。

重写1 个

CurveFactory（原 LaunchFactory 重写）

发币入口：部署 Token 和它专属的 Curve、把 10 亿全部铸给 Curve、收创建费、可选首购、登记参数。毕业时接 Curve 的通知，调 Executor 建池；建池失败可被任何人重试。管理运营参数（开盘市值、毕业阈值、税率曲线）。

招商处，但现在不再直接开店，而是给每个商户发一个预售摊位。摊位卖够钱了，招商处负责把它搬进商场。
改动：现有 launch() 的建池、放币、锁 LP 逻辑全部挪到 Executor，这里只剩部署 + 登记 + 毕业调度。
新写每币一个

BondingCurve

摆摊本体。持有该币的全部代币和买家投进来的 USDC。buy(usdcIn) / sell(tokenIn) 按恒定乘积定价，虚拟储备 phantomQuote 决定统一开盘价。每笔收 1% 手续费（只收 USDC 那一边），直推 75% 创作者 / 25% 国库。前 5 秒递减狙击税。达到阈值的那笔买单：截断多余部分退款、标记毕业、通知 Factory、尝试当场建池。sweepForGraduation() 只能被 Factory 调一次。没有 addLiquidity / removeLiquidity。

楼盘预售处。只有开发商一个窗口，价目表公示，卖得越多越贵；可以退房，不能开二手中介。卖够指标那一秒关窗，预售款全部转成公共产权。
规模：约 350–450 行，是整条路线的核心和最大审计对象。用户本金全程在这里。
新写1 个

GraduationExecutor

搬家工。从 Curve 接过 10,000 USDC 和预留代币，按曲线收盘价在我们的 V3 上建池、初始化价格、mint 一个全范围双边仓位（USDC 与代币按当前价配比），多出来的代币交给 Locker 永久锁（Arc 禁止 burn 到零地址），LP NFT 交给 FeeLocker 登记。要处理 tick 对齐、6 位 / 18 位精度、代币地址排序两种情况。

搬家公司 + 装修队。把预售处的钱和剩下的房子一次性搬进商场，按收盘价挂牌，地契送去保险箱。
规模：约 200 行。难点是价格连续：收盘价 = 开盘价，不能跳。可复用现有 PriceMath。
小改

LaunchToken

基本不变。可以删掉现在的 20 区块窗口限购（防狙移到 Curve 的递减税里），变成纯 ERC20 + 链上元数据。

统一店面，装修图纸一样，只是不再自带"开业限购牌"，那块牌子挂到预售处去了。
改动：删 10 行。可选：毕业前禁止转账到非 Curve 地址，防止有人拿币另开池子（pons 没做，建议也不做）。
小改

FeeLocker

毕业后的地契保险箱 + 分账柜台，和现在一样。唯一改动：register() 允许 Executor 调用（现在只允许 Factory），并多存"锁住的多余代币"。

同一个保险箱，多放一格给搬家时多出来的房子。
改动：约 20 行。
不变

Treasury

完全不变。曲线阶段的 25% 和毕业后的 25% 都进这里，82/18 回购销毁照旧。

商场公账，收钱的口子多了一个，规矩没变。
改动：0。

方案 A 合计

自研 6 个：CurveFactory、BondingCurve、GraduationExecutor、LaunchToken、FeeLocker、Treasury。Uniswap V3 那 4 个沿用已部署的。链下 Keeper 少一项活（曲线阶段手续费每笔直推，不需要 collect），多一项活（监控卡在 Swept 的币并补建池）。

3. 方案 B：曲线 → Uniswap V4 + Hook（= pons v2），多出什么

要等 9.16 Arc 主网官方 V4 地址（PoolManager、PositionManager、Permit2、Quoter）。在方案 A 的基础上再加：

合约作用为什么 V3 不需要
新写 LaunchHook挂在 V4 池上的钩子。池费设 0，每笔 swap 由 Hook 从 USDC 那一边抽 1%，当场分给创作者和国库，不再需要 Keeper collect。可在 Hook 里做毕业后的防狙。地址必须"挖"出来（V4 要求 Hook 地址的特定 bit 表示权限）。V3 没有钩子，手续费只能攒着 collect
新写 V4 LockerV4 的仓位不是 ERC721 而是 PositionManager 里的记录，锁法不同，要单独写。V3 用现有 FeeLocker 直接锁 NFT
新写 GraduationGuardV4 建池比 V3 多很多拒绝条件（Hook 校验、tickSpacing、Permit2 授权），pons 专门写一个无状态预检合约，确保曲线钱倒出来之前池子一定能建。V3 建池条件简单，Executor 内部检查即可
新写 FeeEscrow（可选）pons 把曲线阶段和 Hook 阶段的手续费统一进一个托管合约再结算给创作者。我们用 FeeLocker 的 claimable 模式可以替代。可选
Executor 重写建池走 PoolManager.initialize + PositionManager.mint + Permit2 授权那一套，和 V3 完全不同。—

方案 B 合计

自研 9–10 个，全部要审计，其中 Hook 是 2025 年出过多起漏洞事件的新攻击面。Arc 主网前无法在测试网跑通——测试网没有 V4；理论上 BUSL 允许我们非生产用途自部署 V4 预演，但主网对接官方地址时 Hook 地址要重新挖、部署脚本要重做，等于做两遍。

4. 曲线的账怎么算（一个例子）

让老板和客户看得懂"开盘价、毕业时池子里有多少钱、多出来的代币去哪了"。

参数值说明
总供应 S1,000,000,000全部铸给曲线
虚拟储备 phantomQuote5,000 USDC决定统一开盘市值 = 5,000 USDC，这笔钱不是真的，只是公式里的常数
毕业阈值10,000 USDC买家真金白银投进来的钱达到这个数就毕业
k = phantomQuote × S5,000 × 10⁹恒定乘积
预留代币 = S × phantom / (phantom + 阈值)333,333,333毕业时留给池子的那份，刚好使"曲线卖完 = 钱攒够"同一时刻发生
曲线阶段卖出666,666,667 枚，换回 10,000 USDC这些是买家手里的币
收盘价 = 开盘价（新池）(5,000 + 10,000) / 333,333,333 = 0.000045 USDC毕业市值 45,000 USDC，是开盘的 9 倍
新池实际能配对的代币10,000 / 0.000045 ≈ 222,222,222全范围仓位两边价值必须相等：10,000 USDC 对 10,000 USDC 的币
多出来的代币≈ 111,111,111（11.1%）因为虚拟储备那 5,000 不是真钱。pons 的做法是连同仓位一起永久锁进 Locker；也可以转 0x…dEaD 等效销毁。这 11% 是曲线模式的"隐藏成本"，要在文档里讲清楚

6. 什么情况下值得做

做方案 A 的前提

老板明确要"毕业迁移"作为产品叙事，而不只是要"公平发射"（后者现在已经有）
审计预算到位（曲线是本金主路径，必须审完再上）
接受 9.16 首发用当前路线，曲线作为二期新 Factory 上线，老币不动

做方案 B 的前提

方案 A 的全部前提
9.16 后官方 V4 地址已公布且稳定运行一段时间
有能写和审 V4 Hook 的人，这是 2025 年最新的攻击面
