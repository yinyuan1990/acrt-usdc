# 08 · 静态分析报告（Slither + Aderyn）

> 日期：2026-09-02 · 范围：`contracts/src/**`（LaunchFactory / LaunchToken / FeeLocker / Treasury / PriceMath / SimpleDescriptor，约 700 行）· Uniswap V3 为官方字节码不在范围内
> 工具：Slither 0.11.6（Trail of Bits）、Aderyn 0.6.8（Cyfrin）。运行脚本：`ops/static-analysis.sh`、`ops/aderyn.sh`、`ops/contracts-check.sh`；原始报告在服务器 `/opt/arclaunch/contracts/audit/`。
>
> **定位说明**：这是规则式静态扫描 + 人工复核，属于上线前自查，**不是审计，不能对外宣称"已审计"**。
>
> **2026-09-07 第二次复跑**（合约 v2.6：CREATE2 + 空池拨价 + `SwapGuard` TWAP 地板 / 冲击上限 + 分批回购）：Slither **2 High / 40 Medium / 20 Low**，Aderyn 0 Critical / 1 High / 13 Low；60/60 单测通过。**两条 High 都是 `weak-prng` 误报**：`SwapGuard.twapSqrtPriceX96` 的 `(index + 1) % cardinality` 是 Uniswap 观测环的下标计算（照搬 OracleLibrary），不是随机数；`LaunchFactory._salt()` 用 `blockhash(block.number - 1)` 只求"上一块出来之前算不出地址"，并不依赖它不可预测——同块抢跑由 `_preparePool` 的空池拨价路径兜底，没有任何资金逻辑建立在这个哈希上。Medium 的增量来自新库：`TickMath`/`SwapGuard` 里的 `mulDiv` 报 divide-before-multiply（Uniswap 原版同样如此），`observe` / `observations` / `slot0` 多返回值解构报 unused-return，`== 0` 哨兵判断报 incorrect-equality；`LaunchFactory._repriceEmptyPool` 先 `swap` 再写 `_repricing = 0` 报 reentrancy-no-eth（`launch` 整体 `nonReentrant`，回调里只读）。**没有新类别**。
>
> **2026-09-07 复跑**（合约 v2.5：`ecoFund / feeRecipient / locker.treasury` 改 immutable、删 `setFeeRecipient / setTreasury`、`Treasury.configure` write-once）：Slither 0 High / **19 Medium / 14 Low**，Aderyn 0 Critical / 1 High / 10 Low；50/50 单测通过。Medium 多的两条都是 `Treasury`：`lastExecutedAt == 0`（"首个周期立即可跑"的哨兵判断，报 incorrect-equality）和 `execute` 里 `safeTransfer(ecoFund)` 之后写 `lastExecutedAt`（整个函数 `nonReentrant`，报 reentrancy-no-eth）。删掉两个 setter 反而少了一条 Aderyn Low（缺零地址校验）。**没有新类别**。
>
> **2026-09-05 复跑**（合约 v2.3：税币模式（营销 / 团队双地址）+ `LaunchParams.payout` + 5 字段 `Socials`）：Slither 0 High / **17 Medium / 13 Low**，Aderyn 0 Critical / 1 High / 11 Low；40/40 单测通过。
> Medium 从 13 → 17 是代码变多带来的**同类项**（新增一条是 `FeeLocker._payTax` 读 `taxConfig()` 的解构 + 其后的 `_push`）：`toConvert == 0`、`usdcFromTax == 0`、`liquidity == 0`、`ret.length == 0` 这类空值判断被报"严格相等"（非余额相等，良性）；`distribute` 里多了一次 `_push`（税给创作者）被报"外部调用后写状态"（整个函数 `nonReentrant`，写的是失败兜底 `claimable`）；解构 Uniswap 视图返回值被报 unused-return。**没有新类别**。
> ⚠️ 坑：Slither 的 `--json` **不会覆盖已存在的文件**（日志里一句 "overwrite is prevented" 就静默用旧报告），今天上午两次"结果一致"其实读的是 9.2 的旧 JSON。`ops/contracts-check.sh` / `ops/slither-run.sh` 已改为先 `rm -f audit/slither.json`。

## 逐条复核

### 已修复（加固）

| 发现 | 位置 | 修复 |
|---|---|---|
| ERC20 `approve/transfer` 未用 SafeERC20（Aderyn L-10/L-11，Slither unused-return） | `Treasury.execute/convert`、`FeeLocker.claim` | 改为 `forceApprove` / `safeTransfer` |
| `nonReentrant` 不是第一个修饰符（Aderyn L-5） | `Treasury.convert` | 调整顺序 |
| `setPool` 无零地址检查、无事件（Aderyn L-7/L-8） | `LaunchToken.setPool` | 加 `ZeroAddress` 检查与 `PoolSet` 事件 |
| 构造函数地址参数无零检查（Slither missing-zero-check） | `LaunchFactory` 构造函数 | 加检查 |
| `positionManager.mint` 返回的 liquidity 未校验 | `LaunchFactory._mintLocked` | `liquidity == 0` 时 revert `NoLiquidity` |

### 判定为误报 / 有意设计（不改）

| 发现 | 位置 | 理由 |
|---|---|---|
| Aderyn H-1 外部调用后改状态（10 处） | `launch`、`distribute`、`execute`、`register`、`markGraduated` | 前三者有 `nonReentrant`；后两者的"外部调用"是 view（`ownerOf`/`balanceOf`）。工具不识别 OZ 修饰符 |
| Slither reentrancy-no-eth ×3 | `FeeLocker.distribute` | 有 `nonReentrant`；`_push` 用低级 call 是为了黑名单兜底 |
| Slither divide-before-multiply | `LaunchFactory._floorTick` | `tick / spacing * spacing` 就是向下对齐到 tick 间距，有意为之 |
| Slither incorrect-equality ×2 | `LaunchToken._update`（`block.number == launchBlock`）、`Treasury.execute`（`bal == 0`） | 有意的精确判断 |
| Slither unused-return ×7 | 解构 `slot0()` / `positions()` / `mint()` 的部分返回值；`_initialBuy` 忽略 `amountOut` | 解构时忽略不需要的字段；首购的滑点由 `minTokensOut` 参数保护 |
| Slither timestamp | `deadline: block.timestamp` | Uniswap 标准用法 |
| Aderyn L-9 string 可 immutable | `LaunchToken.logo/description` | Solidity 不支持 string immutable |
| Aderyn L-1 中心化风险 | `onlyOwner` 参数函数 | 设计如此；owner 主网前转多签 |
| Aderyn L-6 PUSH0 | 全部 | Arc 为 Osaka 基线，支持 PUSH0 |
